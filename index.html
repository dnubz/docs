Bagian 1: Bedah 7 Bugs (5 Server + 2 Tauri Desktop)

Bug #1 — Import Bug (Missing Module Exports & Imports)

Lokasi: server/src/core/domain/entity/mod.rs, server/src/port/inbound/service_trait.rs, dan server/src/core/service/service.rs.
Penyebab: Di file soal asli (app.zip), 9 file entity belum di-export dengan pub mod di entity/mod.rs, dan semua pernyataan use crate::... untuk DTO, Entity, serta Trait dihapus dari service_trait.rs dan service.rs. Akibatnya muncul error cannot find type ... in this scope.

Perbaikan: Export semua entity, misalnya pub mod manufacturer;, pub mod medicine_type;, pub mod operator;, pub mod order;, pub mod order_item;, pub mod order_status;, pub mod race;, pub mod role;, dan pub mod warehouse_inventory;. Tambahkan kembali import DTO, Entity, dan Trait yang dibutuhkan.

Bug #2 — Trait Bug (Method dispatch_operator Hilang di Trait)

Lokasi: server/src/port/inbound/service_trait.rs. Handler dan implementasi memanggil method ini, tetapi kontrak ServiceTrait lupa mendeklarasikannya.

fn dispatch_operator(&self, operator_id: i32, order_item_id: i32)
    -> impl Future<Output = Result<(), StatusCode>> + Send;

Bug #3 — Async/Await Bug (Lupa .await di Axum Handler)

Fungsi async menghasilkan Future, bukan langsung Result. Tambahkan .await sebelum melakukan match.

let order_items = service.view_order_item().await;
let operators = service.view_operator_list().await;

Bug #4 — Ownership / Borrowing Bug (Vector Tidak mut)

Variabel Rust immutable secara default. Tambahkan mut pada vector yang menggunakan push(), termasuk di view_operator_list, view_order_item, dan view_task_list.

let mut operator_data = Vec::new();
operator_data.push(operator_details);

Bug #5 — ActiveModel Bug (availability Tidak Di-Update saat Dispatch!)

Tanpa mengubah availability saat dispatch, kurir tetap tampil tersedia dan dapat dipilih berkali-kali.

let operator_active = OperatorActiveModel {
    id: ActiveValue::Unchanged(operator_id),
    availability: ActiveValue::Set(0), // 0 = On Duty
    ..Default::default()
};

Bug #6 — React / TypeScript Bug (Tipe Operator.id Salah!)

Backend mengirim i32 sebagai JSON number; samakan model frontend dengan id: number, bukan string.

export type Operator = {
    id: number;
    fullname: string;
    codename: string;
};

Bug #7 — Rust Tauri Bug (Missing Input Validation di Controller)

Tambahkan validasi ID sebelum HTTP request di dispatch_operator dan pickup_medicine.

if operator_id <= 0 || order_item_id <= 0 {
    return Err("Invalid operator or order item".to_string());
}

Bagian 2: 2 Code Optimizations (Weight 5 — 8.09 PTS)

Optimasi #1 — get_order_item Full-Table Scan → Direct SQL Filter

Hindari memuat seluruh order item ke RAM hanya untuk mencari satu ID. Filter langsung pada database dan eager-load relasi yang dibutuhkan.

let order_item = OrderItem::load()
    .filter(order_item::Column::Id.eq(order_item_id))
    .with((Medicine, Manufacturer))
    .with((Order, Warehouse))
    .with(OrderStatus)
    .with(Operator)
    .one(&self.database_connection)
    .await;

Optimasi #2 — Fix N+1 Query Problem di view_warehouse_list

Panggil load_all_warehouse_inventory() sekali di luar loop, lalu kelompokkan hasilnya menggunakan HashMap<i32, Vec<WarehouseInventoryItem>>.

let warehouses = self.repository.load_warehouses().await?;
let all_inv = self.repository.load_all_warehouse_inventory().await?;
let mut inv_map: HashMap<i32, Vec<WarehouseInventoryItem>> = HashMap::new();
for item in all_inv {
    inv_map.entry(item.warehouse_id).or_default().push(item);
}
for warehouse in warehouses {
    let items = inv_map.remove(&warehouse.id).unwrap_or_default();
}

Fitur #2 — Courier Recommendation (Weighted Scoring & Sorting)

Rank kurir AVAILABLE menggunakan jarak ke manufacturer (65%) dan kecocokan regional (35%). Sertakan region pada Location DTO/model dan eager-load relasi Region.

const MAX_DIST = Math.hypot(1000, 800);
const W_DIST = 0.65;
const W_SPEC = 0.35;
function scoreCourier(c, item) {
    const dist = distance(c.x_position, c.y_position,
        item.pickup.x_position, item.pickup.y_position);
    const distScore = Math.max(0, 1 - dist / MAX_DIST);
    const specMatch = c.region_specialty === item.destination.region ||
        c.region_specialty === item.pickup.region;
    return (W_DIST * distScore + W_SPEC * Number(specMatch)) * 100;
}

Panduan Konsep Rust untuk Pemula (Berdasarkan Kode App)

Rust terkenal dengan sistem keamanannya yang ketat tanpa menggunakan Garbage Collector. Berikut konsep kunci Rust yang digunakan di project ini.

1. Ownership & Borrowing

Ownership menentukan pemilik nilai. Borrowing memungkinkan fungsi meminjam referensi tanpa mengambil alih kepemilikan. Nilai otomatis di-drop saat keluar dari scope.

fn main() {
    let nama = String::from("Amiya");
    cetak_nama(&nama);
    println!("Halo lagi {}", nama);
}
fn cetak_nama(n: &String) { println!("Nama: {}", n); }

Di aplikasi, &self pada method service meminjam instance Service, bukan mengambil kepemilikannya.

2. Error Handling: Result<T, E>, Option<T> & Operator ?

Option merepresentasikan nilai yang mungkin kosong; Result merepresentasikan operasi yang bisa berhasil atau gagal. Operator ? meneruskan error ke pemanggil.

fn bagi(a: f32, b: f32) -> Result<f32, String> {
    if b == 0.0 { Err(String::from("Tidak boleh membagi nol!")) }
    else { Ok(a / b) }
}
fn kalkulasi() -> Result<f32, String> {
    let hasil = bagi(10.0, 2.0)?;
    Ok(hasil * 5.0)
}

3. Smart Pointer: Arc<T>

Arc memungkinkan beberapa thread berbagi kepemilikan data dengan reference count atomik. Clone pointer tidak menggandakan data.

let service = Arc::new(new_service(repository));
let generator = tokio::spawn(run_event_generator(Arc::clone(&service)));
let movement = tokio::spawn(run_courier_movement(Arc::clone(&service)));
let server = new_server(service);

4. Traits & Generics

Trait mendefinisikan kontrak perilaku. Generic dengan trait bound dapat menerima tipe apa saja yang memenuhi kontrak.

trait PengantarBarang { fn antar(&self, paket: &str); }
struct KurirMotor;
impl PengantarBarang for KurirMotor {
    fn antar(&self, paket: &str) { println!("Antar paket {} pakai motor!", paket); }
}
fn kirim<T: PengantarBarang>(kurir: T, nama: &str) { kurir.antar(nama); }

5. Macros & Attributes

Attribute seperti #[tauri::command] dan #[derive(...)] memberi instruksi compiler untuk menghasilkan boilerplate.

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
struct Obat { id: i32, nama: String, jumlah: i32 }

#[tauri::command(rename_all = "snake_case")]
async fn dispatch_operator(operator_id: i32, order_item_id: i32) { /* ... */ }

6. Struct Update Syntax & Default

..Default::default() mengisi field yang tidak disebutkan dengan nilai default.

let order_item_active = OrderItemActiveModel {
    id: ActiveValue::Unchanged(order_item_id),
    status: ActiveValue::Set(4),
    courier_id: ActiveValue::Set(Some(operator_id)),
    ..Default::default()
};

Bedah Struktur Folder Server (Hexagonal Architecture)

Struktur server/src menerapkan pola Ports and Adapters untuk mengisolasi aturan bisnis dari framework web dan database.

Peta Alur Data Hexagonal

  1. Tauri mengirim HTTP request dengan payload JSON.
  2. Inbound adapter (server.rs) membaca payload dan memanggil inbound port.
  3. Inbound port (service_trait.rs) mendefinisikan operasi service.
  4. Core mendefinisikan entity dan DTO, lalu menerapkan aturan bisnis.
  5. Outbound port (repository_trait.rs) mendefinisikan operasi penyimpanan.
  6. Outbound adapter (repository.rs) menjalankan query, eager loading, dan transaksi Sea-ORM.
  7. MySQL menyimpan data. Konfigurasi ada di db.rs dan skema awal di create+insert.sql.
Analogi Colokan & Kepala Charger:
  • Port: kontrak interface yang menetapkan bentuk interaksi.
  • Adapter: menyesuaikan teknologi luar, misalnya Axum HTTP/JSON atau Sea-ORM/SQL.
  • Core: logika inti yang tidak bergantung pada teknologi luar.

Penjabaran Tiap Folder & File

1. Folder core/

Otak sistem; tidak boleh bergantung pada Axum atau HTTP.

  • core/domain/entity/: struct tabel database Sea-ORM.
  • core/domain/dto/: format request dan response JSON.
  • core/service/service.rs: aturan bisnis dispatch.

2. Folder port/

Trait menjadi kontrak antara Core dengan dunia luar.

  • port/inbound/service_trait.rs: operasi yang dapat dipanggil adapter.
  • port/outbound/repository_trait.rs: operasi database yang dibutuhkan service.

3. Folder adapter/

Implementasi teknis menggunakan Axum dan Sea-ORM.

  • adapter/inbound/server.rs: menerima HTTP, routing, dan memanggil service.
  • adapter/outbound/repository.rs: query SQL dan transaksi.

4. Folder database/ & File Root src/

  • db.rs: koneksi pool MySQL.
  • create+insert.sql: skema dan data seed.
  • terra-map-layout.json: koordinat peta Terra.
  • main.rs: composition root.
  • event_generator.rs: task background Tokio.

Mengapa Ada File adapter.rs di Sebelah Folder adapter/?

Rust memerlukan deklarasi modul untuk mengekspor isi folder:

pub mod inbound;
pub mod outbound;

Mudah Diuji dan Fleksibel

Service yang bergantung pada RepositoryTrait dapat diuji dengan mock tanpa database nyata. Implementasi database dapat diganti tanpa mengubah logika bisnis.

Alur Request dari Tauri ke Database

1. Tauri IPC & HTTP Client

desktop/src-tauri/src/model/api_client.rs menggunakan Reqwest untuk POST ke server lokal.

  • Payload: operator_id dan order_item_id.
  • Target: http://127.0.0.1:3000/dispatcher/dispatch-operator.
  • Async call via Tokio.
let response = self.client
    .post(format!("{}/dispatcher/dispatch-operator", self.base_url))
    .json(&request)
    .send()
    .await;
2. Axum Inbound Adapter

Axum mencocokkan URL, mem-parse JSON payload, memanggil Service, dan mengembalikan response.

async fn dispatch_operator(State(service): State<Arc<S>>,
    Json(payload): Json<DispatchOperatorRequest>) -> impl IntoResponse {
    let result = service.dispatch_operator(payload.operator_id, payload.order_item_id).await;
    match result {
        Ok(_) => (StatusCode::OK, "Operator dispatched").into_response(),
        Err(status) => (status, "Error dispatching operator").into_response(),
    }
}
3. Inbound Port (Service Trait)

Trait menetapkan kontrak antara web adapter dan service.

pub trait ServiceTrait: Send + Sync {
    fn view_operator_list(&self) -> impl Future<Output = Result<Vec<OperatorDetailsResponse>, StatusCode>> + Send;
    fn view_order_item(&self) -> impl Future<Output = Result<Vec<OrderItemResponse>, StatusCode>> + Send;
}
4. Core Domain Service

Service memvalidasi ketersediaan courier, role, dan status order sebelum membuat ActiveModel update.

if operator.availability != 1 || operator.role_id != 2 {
    return Err(StatusCode::BAD_REQUEST);
}
if order_item.status != 3 {
    return Err(StatusCode::BAD_REQUEST);
}
5. Outbound Port (Repository Trait)

Kontrak database yang tidak mengikat Core pada satu jenis database.

pub trait RepositoryTrait: Send + Sync {
    fn find_operator(&self, operator_id: i32) -> impl Future<Output = Result<OperatorModel, DbErr>> + Send;
    fn dispatch_operator(&self, operator: OperatorActiveModel, order_item: OrderItemActiveModel) -> impl Future<Output = Result<(), DbErr>> + Send;
}
6. Sea-ORM Outbound Adapter

Repository menjalankan query dan transaksi atomik.

let tx = self.database_connection.begin().await?;
operator.update(&tx).await?;
order_item.update(&tx).await?;
tx.commit().await?;
7. MySQL Database

Database menyimpan operator, order item, obat, warehouse, region, dan activity log.

CREATE TABLE IF NOT EXISTS `operator` (
  `id` INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `codename` VARCHAR(255) NOT NULL,
  `role_id` INT NOT NULL,
  `x_position` FLOAT NOT NULL,
  `y_position` FLOAT NOT NULL,
  `availability` BOOLEAN NOT NULL,
  FOREIGN KEY (`role_id`) REFERENCES `role`(`id`)
);
